# 安全模型与限制

## 信任与攻击面

操作者/管理员持有策略、Hook 配置、安装代码及实际权限。仓库文档、注释、日志、工具内容和模型产生的参数都是数据，不得授予权限。策略文件不能从事件 cwd 自动发现；必须由固定 Hook 命令显式指定。只有可信调用方可决定结构化操作类别。CLI evaluate 是决策 API，不是执行代理。

本项目主要防止错误与越界请求，不宣称隔离能够任意执行代码的恶意同用户进程。可写策略/脚本、可禁用 Hook、可换解释器/PATH/启动文件的环境不能形成可靠安全边界。用 OS 权限、沙箱、托管配置、可信 PATH 和最小凭据授权保护实际运行环境。manifest 是修改检测，不是签名或受信证明。

Windows 命令生成拒绝 cmd.exe 展开/控制字符，不把 list2cmdline 当作 Shell 转义。
POSIX 安装路径含这些字符时，Windows 覆盖命令固定为 exit 2，不能直接迁移为 Windows 安装。
实际 Windows 宿主启用仍为 Unverified；Claude 生成 exec-form command/args，避免 Shell 拼接。

## 约束覆盖

- 显式路径按组件检查工作区、保护前缀和敏感名称；处理现存 symlink 和 `..`。检查存在 TOCTOU、硬链接、别名、大小写和平台特有路径风险。无法完整判断进程可能读写的文件。
- Shell 采用窄语法识别，不是解释器。组合、替换、转义、环境赋值、脚本和未知工具保守处理。即使 git status 等常规语法也假设可执行文件、环境和 Git 配置可信（如 fsmonitor 可触发程序）；宿主沙箱必须保留。
- 已测的 Codex 0.160.0 与 0.164.0-alpha.11.1 Bash Hook 均未提供可信实际工具 workdir，事件 cwd 仅是会话目录。相对目标不借用该目录放行；按 unknown 处理，精确 development_commands 也不例外。绝对文件参数和单个绝对 `git -C` 只解决这些窄语法的显式目标，不证明进程所有读写都局限于此。`pwd` 可继续执行，只披露目录元数据，不声明具备完整工作区保密性。
- 操作者配置的 development_commands 是完整 argv 信任入口。脚本内容、依赖、测试插件及子进程可变化，白名单并不能保证没有副作用。不要用白名单保护敏感数据；应放入实际沙箱/文件权限。
- 危险 Git、数据删除、外部与生产类别默认 REQUIRE_APPROVAL；Adaptive 在没有经验证审批桥接的 Codex 路径拒绝它们。可信识别的敏感访问、保护路径修改和工作区外目标也拒绝。原生 prefix_rule 只是补充，换参数顺序、路径、包装器或不同执行路径可能不匹配。没有“允许所有 git”之类规则。
- 未知 MCP schema、递归搜索、解释器和特殊宿主工具未实现语义。Claude default 可 ask，Codex 无审批桥接则 deny；没有自签批准、自动批准或重试绕过。
- 共享修订比较可检测比较前的变化，但检查到写入间仍有竞争；不是锁。SQLite 并发审计通过真实多进程测试，不能等同文件写入隔离。多 Agent 推荐独立 worktree/原子文件工具。

## 故障和模式

策略加载失败、JSON 异常、未知输入或 worker 崩溃不回显内容，返回拒绝。默认 worker 2 秒、宿主 5 秒；内部期限只在外层 Python 已成功启动时有效。外层解释器缺失、脚本导入失败、宿主先取消或配置未受信可能根本没有拒绝响应。

真实 Codex 0.160.0 与 0.164.0-alpha.11.1 已复现：未信任 Hook 不运行；Hook 崩溃、宿主期限超时及坏输出继续工具。内部 watchdog 不修复这个宿主缺口。Claude onFailure=block 和 Cursor failClosed 的具体宿主效果本轮未验证。不能声称全链路 fail-closed。

OBSERVE 对正常解析的策略判定只观察，返回空对象，不跳过宿主限制。Adaptive 对 UNKNOWN 也只返回空对象：这是覆盖未知，而非 ALLOW 或宿主许可。无效输入/配置不能可靠确定安全性，仍拒绝。Adaptive/PROTECT/STRICT 中审计不可用拒绝；OBSERVE 的审计故障只提示。模式不改变平台权限和 Hook 覆盖面。

首次安装默认 Adaptive 是可用性与覆盖边界的取舍：可信识别的敏感路径、越界和高风险命令会新增拒绝，但缺少实际执行目录的相对命令保持 UNKNOWN，由宿主 Sandbox/审批处理。它没有把 UNKNOWN 变成安全结论，内部 worker 故障仍会拒绝。操作者须保留实际沙箱、权限和最小凭据；既有 bundle 不自动改变或降级。上下文调查未找到可用的可信实际目录，见[受限方案](execution-context.md)。

## 日志与恢复

审计采用数据最小化：只保存固定类别和决策字段，不记录命令、argv、路径、环境变量、session id、工具结果、异常原文或敏感值的哈希。新审计目录 0700、文件 0600（POSIX），SQLite 无远程服务；Windows ACL 需操作者保证。宿主可能另存完整输入/输出，不受此默认脱敏承诺覆盖。

真实 Codex 会在被拒绝的 patch 结果中回显 patch 输入。若秘密已在工具输入或历史中，拒绝不能撤回它；适配器也不控制宿主日志。敏感读写测试将合成 canary 仅放在文件内、不放进 patch，确认被拒绝后文件内容未进入对应工具结果，不能外推为宿主全局脱敏。

审计不是不可篡改证据，不提供自动轮转/清理；配置私有目录和留存期。安装目录旁的独立审计目录不会被卸载删除。自动卸载只处理原安装清单匹配文件；配置修改、备份恢复和停用均是操作者显式操作。没有全局配置更新或生产部署逻辑。

安装使用私有 staging、独占目标、独占文件创建、清单最后发布、校验后最后删除 `.udg-installing`。公开校验拒绝带标记的 bundle。捕获异常时仅删除内容仍匹配的自有文件；用户修改、新增文件和归属不确定的半写入连同未完成标记保留。骤停可能留下目标或私有 staging，不能将其启用；恢复时先保存用户文件、人工清理或选新目录，安装器不覆盖重试。不是文件系统事务、原子目录提交、并发恶意进程隔离或断电持久性保证；相同 OS 身份的攻击者仍可移除标记/篡改清单。

快捷 Skill 安装复用同一发布/回滚协议，只允许项目内的固定 Skill 目录，不安装运行时或修改 Hook；各平台目录放置不等于真实宿主加载已验证。运行时省略目标时使用项目内 `.guardrails/udg-bundle` 并拒绝向工作区外的路径重定向；显式外部目标仍由操作者选择。项目内代码/策略可能可写，快捷安装并未提供新的隔离边界。安装清单与内容副本是修改检测，不是发布签名；升级不会覆盖用户更改。
